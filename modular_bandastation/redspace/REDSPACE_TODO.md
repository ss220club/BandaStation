## Тестовые сценарии MVP

- [ ] Штиль: фон `0`, источников нет, система почти не потребляет время.
- [ ] Фон: изменение фона меняет показания пустых и уже созданных ячеек.
- [ ] Источник: локальное значение уменьшается с расстоянием и не меняет всю карту.
- [x] Волна: ручной замер подтвердил плавное перемещение, обновление dirty-ячеек, причину `волна перемещается` и удаление по lifetime.
- [ ] Границы: значения `3/4` и `6/7` не дёргают диапазон туда-сюда.
- [ ] Шторм: вход вызывает один сигнал и ограниченное число событий.
- [x] Стабилизатор: отрицательный вклад локален, расход ресурсов работает, отключение возвращает поле через затухание.
- [x] Датчики: одинаковый тайл даёт одинаковое точное значение, история и stale-статус работают; видимость действий отвязки подтверждена ручной проверкой.
- [x] Очистка: удаление источника освобождает его состояние и не оставляет таймеров/эффектов.
- [x] Ограничение карты: космос, away-миссии и виртуальные домены не подключаются автоматически.

## Не входит в MVP

- [ ] Процедурная генерация миров и отдельных измерений.
- [ ] Отдельная постоянная ячейка состояния для каждого тайла карты.
- [ ] Ghost HUD с обзорной картой поля редспейса по гексагональным ячейкам. Планируется после MVP через NanoMap/TGUI, с обновлением только активных зон.
- [ ] Постоянный тик по всем мобам в зоне.
- [ ] Большой пул уникальных существ.
- [ ] Автоматическое уничтожение станции при высоком значении.
- [ ] Игровой способ повышать возмущение игроками до проверки базового цикла.
- [ ] Интеграция существующих блюспейсных объектов до реализации сигналов.
- [ ] Локальное глушение радиосвязи в зонах высокого возмущения после выбора модульного integration hook (post-post-MVP).
- [ ] Полноценные сценарии выше `10`: локальные или глобальные вторжения, включая их контент и правила завершения (post-post-MVP). Override принадлежит сценарию-владельцу и не снимается контроллером автоматически.
- [ ] Две политики завершения сценариев выше `10`: эндраунд и административное управление (post-post-MVP); обе политики управляются владельцем сценария.
- [ ] Добавить post-MVP модели динамики горячих зон через отдельный `/datum/redspace_source_behavior`: статичную, колебательную, затухающую, нарастающую и импульсную.
- [ ] Спроектировать отдельную систему мобов редспейса: spawn policy, контекст происхождения, лимиты зоны, профили существ и lifecycle будущего вторжения без постоянного тика по всем мобам.

## Рекомендуемый порядок

1. Контекст раунда, коэффициент мостика и API источников.
2. Гистерезис, dirty-обработка, журнал переходов и сигналы.
3. Счётчик, датчик и серверное состояние научной консоли.
4. TGUI консоли с реальными точками измерений.
5. Стабилизатор с питанием, хладагентом и отказами.
6. Реестр событий, безопасный эффект, штормовой эффект и демонический профиль.
7. Демонический профиль, нагрузочные замеры, финальная балансировка и проверка ручного event-only override; полноценные сценарии выше `10` оставить post-post-MVP.

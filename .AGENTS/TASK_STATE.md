# Состояние задач и оркестрация

Рабочие записи — в локальном `task_state/<task-id>/`. Шаблоны версионируются в `.AGENTS/templates/`. Task state хранит контекст, не запускает работу и не выдаёт разрешений.

```powershell
tools/agents/task.ps1 -Action list
tools/agents/new-task.ps1 -TaskId 20261024-example -Title 'Проверяемый результат'
tools/agents/task.ps1 -Action resume -TaskId 20261024-example
```

| Файл | Содержание |
| --- | --- |
| PLAN.md | Цель, владелец, узкие пути записи, исходный HEAD/dirty state, MUST/KEEP/REJECT/CHECK, критерии готовности |
| TODO.md | Короткий вход: статус, сделанное, следующий шаг, последняя проверка и блокер |
| DECISIONS.md | Решения, причины, источник указания и проверяемые допущения |
| EVIDENCE.md | Дата/зона, команда, проверенные входы, PASS/FAIL/SKIP и предел результата |

Статус в TODO: `active`, `blocked`, `done`, `superseded`. `done` — только при выполненной приёмке; блокер содержит отсутствующий вход, замена — ссылку на новую задачу. Для простой завершённой правки отдельная папка не обязательна.

После потери контекста выбери TaskId явно, прочитай TODO, проверь HEAD, dirty state и затронутые файлы. Остальные документы читай по необходимости. `resume` только читает; он не меняет статус. Уточнение пользователя направляет текущую задачу, пока она явно не отменена или заменена.

## Несколько исполнителей

Дополнительные агенты — при прямом разрешении пользователя или явной применимой инструкции. Оркестратор задаёт каждому цель, входы, владельца, точные пути записи, ограничения и критерии результата. У одного task state один писатель. Пересекающийся файл ведёт один интегратор; перед записью перечитывает текущую версию. Общие генераторы, сборки и изменяющие runtime проверки выполняются последовательно.

Разделяй независимые задачи и контекст; не пересылай весь архив обсуждений каждому агенту. Возвращаемый отчёт: что изменено, проверки, ограничения и что осталось. После интеграции проверяй конечное дерево.

Если среда позволяет выбирать reasoning, ориентир: Low — механическая правка, Medium — ограниченная реализация, High — архитектура или разбор состояния/ожиданий. Ultra не использовать. Модель и её доступные уровни сверяй со средой, не прописывай их глобально из проекта.

Функцию цели используй, когда пользователь явно просит поставить цель; она не заменяет PLAN/TODO и не расширяет scope. Никаких автоматических leases, файловых блокировок или FIFO эти утилиты не реализуют — области записи согласуются исполнителями.

Старый `.AGENTS/local/` не использовать для новых записей: на Windows он пересекается с обнаружением skills. Явный `task.ps1 -Action migrate -TaskId <id>` переносит существующую задачу без перезаписи, сохраняя исходник. При передаче набора чужая история задач не экспортируется. Секреты и тяжёлые логи в task state не хранить.

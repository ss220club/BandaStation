# Регрессия запуска: река у границы карты

При проверке воксов обнаружено зависание исходного `spawn_rivers()` до запуска
unit tests. Изменения расы для самого дефекта не требуются: повторный запуск
ранее собранного DMB также воспроизвёл зависание.

Диагностическая сборка с `world.loop_checks = TRUE` показала стек:

```text
/proc/spawn_rivers
SSmapping.setup_rivers
SSmapping.Initialize
Master.init_subsystem
```

Временная инструментированная копия исходника поймала первый выход за границу:

```text
previous = (140, 75, 3)
target = (140, 83, 3)
direction = 6 (SOUTHEAST)
detouring = TRUE
world bounds = (140, 143)
get_step(previous, direction) = null
```

Исходный код заменял текущий turf на `null`, после чего цикл продолжался
с `get_step(null, 0)`, не приближаясь к существующему target.
Исправление сохраняет последний валидный turf, отменяет обход и направляет реку
к target. Для записанного случая следующий шаг должен быть `(140, 76, 3)`.
Оба присваивания шага проверяют результат; удаление любого endpoint завершает цикл.

Регрессионная проверка использует реальный запуск генератора, без тестового API
для направления или подмены `prob()`. В репозитории не найден шаблон управления
общим seed BYOND, поэтому отдельного случайного unit test не добавлено.

После сборки выполнить из корня репозитория:

```powershell
tools/vox/test-vox.ps1 -IncludeHumanoidScreenshots -TimeoutSeconds 600
```

Ожидаемый результат: генерация проходит дальше `Cave Generator terrain generation
finished`, сервер запускает и завершает тесты, создаёт `clean_run.lk` со значением
`Success!`. Проверить `console.log`, `dd.log` и `runtime.log.json`: отсутствие
`Infinite loop suspected`, runtime-ошибок и таймаута. Итоговые результаты общего
прогона следует сохранять рядом с отчётом проверки воксов.

Диагностические wrapper/DMB, временная копия `river.dm` и логи находятся в `tmp/`
и не входят в изменения проекта.
